## 1. 结论与实际边界

- 官方 Superset 6.1.0 MCP 的握手、工具发现、目录调用、已保存图表取数均已真实运行。
- 部署额外提供**身份绑定、单进程串行执行、只读工具白名单**，官方工具及数据库鉴权源码未修改。原生 CLI 零适配的 JWT 多用户调用并未通过，不能隐藏这个差异。
- 现有 LangGraph Agent 已有显式可选路径 `superset_mcp`，实际执行为 **MCP 目录 + REST 受限 Plan 查询 + PostgreSQL**。默认 REST 路径继续保留。

- 本实验仍保留本机演示身份切换。未提供生产 SSO、多节点部署或高并发保证。

## 4. 五种身份：精确人员集合与目录

下面是**含离职人员的授权集合**，不是在职人数。期望来自独立 BFS 和原确定性样本，不按角色名称猜测。HRBP 与 HR 主管在此样本中的集合相同，不意味着两种策略相同。

| 应用身份 | 业务策略 | 官方 MCP 图表人员数 | 可见数据集数 | 合同权限 | 结果 |
|---|---|---:|---:|---|---|
| `employee` | 员工本人 | 1 | 3 | 无 | 集合、REST 对照、负例通过 |
| `manager` | 本人及管理汇报线 | 179 | 3 | 无 | 集合、REST 对照、负例通过 |
| `hrbp` | 本人、HRBP 服务范围及样本策略 | 239 | 5 | 有 | 集合、REST 对照、负例通过 |
| `hr_lead` | 含继承 HRBP 范围 | 239 | 5 | 有 | 集合、REST 对照、负例通过 |
| `admin` | 集团管理线演示身份 | 300 | 5 | 有 | 集合、REST 对照、负例通过 |

应用 `admin` 对应 `v2_admin` 普通业务用户，**不是** Superset `Admin` 角色或 `v2_setup_admin`。业务用户没有 SQL Lab、全库读取或配置管理权限。

员工/主管猜测合同数据集 ID、读取合同图表均被拒绝。公共数据集元数据不含合同列；Agent 中合同明细、筛选和排序依赖也被拒绝。目录结果不向模型转发未审阅描述或 owner 信息。

## 5. 权限、失效与错误语义

| 场景 | 实测结果 |
|---|---|
| 缺失/错误/过期凭据，错误签名、issuer、audience、scope | MCP HTTP 401/403；无开发身份回退 |
| REST 登录 JWT 用于 MCP | 401；同为 Bearer 不表示通用 |
| JWT 指向未知 Superset 用户 | 初始化可成功，业务工具拒绝；没有业务数据 |
| Superset 账号存在但无业务映射 | REST context/人员为空；官方图表返回明确 `NoData`，Agent 拒绝缺失映射 |
| 两个独立身份协议会话交错 | 两轮工号集合保持各自结果；最终部署串行执行工具 |
| 角色的数据集权限撤销 | 新查询、核验、历史/调试、导出关闭 |
| 人员/事件 RLS 单独收窄 | 新查询按新范围；旧历史/调试失效；核验与当前出口一致 |
| 删除员工身份映射 | 新查询、历史/调试拒绝 |
| 管理线能力关闭 | 主管新查询收缩到本人，旧历史失效 |
| 汇报线变为环/孤儿 | 409 拒绝；不继续沿用旧范围 |
| 移除账号的数据集角色、停用账号 | 已签发 JWT 不能继续读取原数据集；恢复后比对原角色和 active 状态 |
| MCP 端点不可达 | 查询、核验、历史、导出返回 503；没有回退到 SQLite/管理员 |
| 工具业务错误或普通 `Error:` 文本 | 不能当作零行；SDK 包装的异常组保留已脱敏的 403/413 |
| 目录分页/大小不完整 | 拒绝；字节上限在 SDK 解析前执行 |
| 结果规模/总计不一致 | 复用原计数与明细完整性检查；不会拿前 N 行冒充全量 |

所有可逆探针仅通过固定实验 Compose 项目执行。`finally` 按捕获的旧值恢复，最后再次 capture 比较；恢复文件留在实验 `.local/probe-recovery.json` 和 `.local/account-recovery.json`。不通过重新初始化猜测原权限。

修复的核验问题：原实现可能从 HR 合同人员快照计算公共查询的参考值；公共 RLS 收窄时，参考范围仍较宽。现在参考计算与 `query_scopes[实际出口]` 相交，事件精确到人员/日期/入离职标记。独立参考仍自行计算聚合，不复用执行结果作为期望值。离线 BFS 另负责证明权限名单，而非让在线核验自我证明。

## 7. 真实模型端到端

使用已加载的 LM Studio `hr-qwen`，实际调用现有 LangGraph，不替换 `call_model`，不下载或重载模型。自动验证的两个问题串行执行，模型候选计划、usage、finish_reason 与 MCP 阶段均保留在证据快照中。

| 身份 | 原始问题 | 实测 |
|---|---|---|
| 员工 | 我能看到多少在职人员？ | 1 人；与独立期望相等 |
| HR 主管 | 我能看到的在职人员按部门分别有多少？请给出合计。 | 226 人、4 个部门分组；分组和合计均相等 |

两次都直接生成可执行候选计划，没有发生规则补齐或模型修正重试。输出节点含 `initialize`、`notifications/initialized`、`tools/list`、`tools/call:list_datasets`，随后明确显示 REST 执行。模型获得授权字段/指标定义，不获得 JWT、密码、管理员账号或任意 SQL 执行工具。

另从实际浏览器切换员工身份，再次提交本人在职人数问题，页面显示 1 人；独立节点调试页显示 8 个节点，MCP 节点展开后可看到真实协议版本、三个公共出口及完整调用阶段。见 [页面实操证据](evidence/superset-mcp-browser.json)。这次页面烟测与上述两个自动模型用例分开记录。MCP 目录节点展示授权阶段已取得的结果，节点自身耗时不代表网络延迟。

## 8. 复核命令及验证限制

已完成：真实协议/权限回归 185 项全部通过；`uv run pytest -q`（172 项）、Ruff、字段文档同步检查、前端 TypeScript、oxlint、生产构建；实际协议/权限回归用 `lab.py run ... validate.py`，模型用 `model_smoke.py`。

完整 `scripts/check.sh` 没有直接执行：其中 `ci-smoke.sh` 固定使用课堂正在占用的 8000/3000。本次分别执行静态检查、单测与构建，并使用独立 18000/13000 的 HTTP/MCP 验证。没有为了跑通 CI 脚本停用课堂环境。

已知限制：

1. 原生 CLI 的 JWT 用户绑定缺口，以及 Flask-SQLAlchemy 并发会话问题，通过显式部署适配层解决；不宣称上游已修复。
2. 官方图表工具的 `total_rows` 不能证明完整性，Agent 继续使用现有 REST 编译器。没有可自由提交 QueryObject 的新自建 MCP 工具。
3. 当前只验证单进程、单机回环地址、小型合成样本和列出的三种只读工具；未验证生产 SSO、远程 TLS、Redis、多节点及高并发。
4. 20 个固定 Plan 全覆盖；自然语言只覆盖表中 2 个问题。有效人员调岗的所有组合、真实 HR 规则与业务口径并未穷举。
5. 上游 HTTP/SQL 多次读取不是单一事务，保留原有前后指纹检查；不是生产级实时撤权版本协议。
6. 测试有一条第三方 Starlette/AnyIO 弃用警告，不影响通过；没有为清除警告升级课堂依赖。
