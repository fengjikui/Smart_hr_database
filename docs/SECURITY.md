# 当前安全与权限边界

## 已实现

1. 会话主体由服务端读取；随机 token 仅存哈希，Cookie 为 HttpOnly/SameSite，POST 查询附带 CSRF 校验。本机限制 Host/Origin、跨站请求、请求体大小与速率。
2. 模型仅生成 Pydantic 白名单 Plan，不接收执行账号、数据库连接或自由 SQL。字段输出、筛选、排序、分组与指标依赖都要授权。
3. 默认通过当前业务用户登录 Superset。平台执行数据集访问控制和三条 Base RLS；技术管理员不能被用作业务查询身份。
4. PostgreSQL 视图计算本人、管理下属、HRBP 服务与继承关系；检测环和无效引用。公开出口和合同出口使用不同只读账号，公开视图物理上没有合同列。
5. 查询返回、导出、历史和多轮恢复检查当前身份、数据与各必需出口授权指纹。必需数据集撤权即拒绝；上游故障不返回伪造空结果，不回退 SQLite。
6. 凭据在 Git 忽略的本机文件，既不进入模型也不进入浏览器。查询结果为私人不缓存响应；CSV 防公式注入并保留工号前导零。

## 必须正确理解的限制

- 身份选择器可任意切换演示用户，不是可信企业认证；仅绑定回环地址。正式上线需 SSO/账号映射/HTTPS/生产 Cookie 配置。
- Superset 不会自行理解 HRBP 和汇报线；这些业务语义仍由 `integrations/superset/schema.sql` 定义，需要业务确认与回归。
- 数据库账号是共享连接账号，直接用它查询不能获得最终员工隔离；最终用户行过滤依赖 Superset 执行 RLS 的路径。禁止向普通用户提供连接凭据或不受控 SQL 入口。
- 基础/合同字段采用物理隔离，其他字段组还依赖应用校验。应用明细/导出开关不会自动禁用 Superset 原生下载和明细菜单。
- 固定 300 人样本；授权快照最多 1000 人、2000 事件标识，超过或不完整就拒绝。当前分页不表示已完成大规模数据库分页。
- 口径和有限 grounding 校验不能证明任意中文问题一定理解正确。教育历史、任职历史、薪资和考勤事实不在当前宽表中。
- 真实生产仍需确认权限责任人、发布审批、数据同步、集中审计、备份恢复和容量；这些不是演示已完成的能力。

具体角色/RLS 配置见 [实施讲义](SUPERSET_SETUP.md)，验证方法见 [测试说明](TESTING.md)。
