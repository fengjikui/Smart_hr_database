# 产品需求与验收范围

## 目标

让主管和 HR 团队在一次现场演示中理解：自然语言能查询哪些数据、授权如何限制结果、口径如何解释、常用查询如何沉淀为看板。产品名“澄观”，示例企业“澄川科技”。所有姓名、组织、薪酬和考勤均为生成的模拟记录。

## 核心用户与任务

- 公司负责人：查看自己全部直属与间接下属，了解人员规模和考勤变化，保存管理指标。
- 事业部负责人：相同问题仅查询自己的管理链，验证跨事业部访问被拒绝。
- 团队主管：查看本团队成员，理解与上级的数据范围差异。
- HRBP：按服务组织授权，与其个人汇报链分离。
- 普通员工：仅查看本人，检验角色与客户端参数不能扩大权限。

## 六个工作页面

1. 数据总览：在职、出勤率、批准加班、异常、半年人员趋势和当前事业部分布。
2. 智能问数：中文问题、示例问法、同身份追问、等待状态、失败重试、可解释答案。
3. 我的看板：保存指标计划，重开后重查；刷新、移除、独立导出授权。
4. 组织与权限：四级组织，按节点查看基础人员，直属/间接人数与字段能力展示。
5. 指标字典：搜索已授权指标，查看定义、来源、别名、负责人和版本。
6. 数据治理：公司负责人查看全合成数据校验、关系模型与自己的查询审计。

## 支持的问题边界

17个指标，单一分组维度，明确日期或今天/本周/上周/本月/上月/本季度/上季度/今年/去年/近30天/近半年，授权内指定组织或员工，基础人员名单和考勤异常明细。人员名单单次最多100条，图表最多展示前12组并可查看完整返回表格。

不支持的条件必须说明，不可静默删条件。已知年龄、性别、排名、同比环比、预测等条件由前置能力检查拦截。模型仍可能误解其他未覆盖说法，需通过现场反馈持续增加基准问题，不能宣称通用问答准确率100%。

## 用户可见的可靠性

- 页面固定显示模拟数据与当前演示身份；数据以2026-09-11为默认截止日，非真实实时公司数据。
- 接口失败时显示原因；模型离线时聊天失败，但固定看板和概览可查询。
- 同一指标在概览、聊天和看板使用同一编译器。
- 模型输入不包含原始人员数据。数值摘要采用程序模板，不做无依据因果解释。
- 会话身份切换清除页面数据和对话状态，未完成旧请求不能覆盖新身份结果。

## 验收

主链路：公司负责人问“我的直属和间接下属分别有多少人”，得到分组结果；查看口径；保存看板；切换研发负责人重新问，范围收缩；请求其他事业部或薪酬明细被拒绝；模型关闭时错误明确。

数据：外键、时间有效性、汇报闭包、考勤覆盖、弹性边界、审批时长、合成标记等规则通过。

权限：匿名访问、伪造身份、CSRF、跨站、未知SQL/字段、其他人看板、撤权、跨身份追问等负向测试通过。

性能：记录本机查询/概览/模型请求的 p50/p95 和查询次数；单路本地模型不假装具备多用户高并发。

可维护性：依赖锁定，分阶段 Git 提交，CI 与可重复测试，配置示例、运行手册和演示脚本齐全。
