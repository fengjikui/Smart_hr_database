# HR 演示 V2 实现记录

本版本主要服务 HR。真实源目前只确认 PostgreSQL、当前宽表、一人一行和人员主键关联；业务口径及权限规则仍是待确认的演示假设。现场演示使用独立 SQLite 数据，不声称已经完成真实 PostgreSQL 接入。

## 数据与目录

- 合成宽表 `people`：300 人、26 字段。字段集合严格限定为 20 个验收问题的 25 个依赖字段，加部门主管关联 `dept_master_id`。工号按字符串保留前导零。
- 固定数据截止日：2026-09-11；固定种子：20260911。模型中的“今年、上周、过去 N 天”以此解释，页面始终显示截止日。
- `backend/hr/v2/schema.py` 定义字段、16 个指标、分组维度及严格查询结构；`registry.py` 补充完整 ID、口语别名、含义、非含义和权限过滤后的目录。
- 目录在 Git 中版本化存储；应用 SQLite 存储角色配置版本、会话、对话历史和审计。26 字段阶段使用轻量索引及按需披露，不引入向量库。
- 当前学校与学历仅代表宽表当前教育记录；985/211 来自演示字典，211 包含985。没有完整历史任职、教育经历和考勤事实。

## 权限

`auth.grants()` 沿 `head_person_id → person_id` 逐员工向上遍历，确定全部管理下属及层级；没有固定32层截断，有循环和无效引用检测。另计算本人 HRBP 服务集合，以及“管理下属中的 HRBP 所服务员工”集合。三者与本人取并集，按人员主键去重。

王承哲管理姜姜，姜姜服务王灏、冯基魁，因此王承哲通过服务继承查看这两人。服务关系不反过来成为管理边，也不会沿任意可见人员继续扩张。部门主管 ID 当前不单独授权。

角色配置包含管理线、本人HRBP服务、下属HRBP继承、字段组、明细、导出。配置管理员先预览新增/撤回人数，再按乐观版本锁应用。查询、下钻、导出、历史恢复均检查当前身份和规则；历史绑定身份、权限配置、可见集合及完整数据指纹，变化后失效。

演示身份切换是回环地址环境的测试机制，不代替生产 SSO。真实上线仍需接入可信身份映射、PostgreSQL 只读连接/数据库侧权限、业务审批及运行监控。

## Agent 与调试

实际使用 LangGraph：身份与历史校验 → 目录检索与披露 → 本地模型生成结构化计划 → 补读/校验/一次修复 → 重新鉴权 → 只读 SQL 执行 → 结果组织与历史保存。

模型只生成白名单查询计划，SQL 由程序编译，值通过参数绑定。模型不能提交自由 SQL。未知字段、不可见字段、无效范围、超期历史事实等被拒绝。

对于明确的自然语言时间和服务范围，程序执行条件绑定，并在独立节点记录模型原始输出、绑定前后差异。学校、专业、年龄和多轮继承等条件另做一致性检查。规则补齐后的成功与模型原始识别成功分别统计，不混为一谈。

节点调试面板展示每步输入、输出、用时、补读与修复分支，以及最终计划、SQL、参数、结果和自然语言摘要。数字摘要从计算结果单元格生成，避免第二次模型调用改写人数和比例。该摘要方式不包含自由生成的业务归因。

## Excel 风格核验表

采用 AG Grid Community 36.1.0。社区版提供表格、列宽调整、列头筛选、排序和分页；内置透视、聚合属于商业功能。本版本通过自有后端完成分组统计，并用 Recharts 绘图，不引入 Enterprise 模块。

参考：[官方功能说明](https://www.ag-grid.com/react-data-grid/key-features/)、[Infinite Row Model](https://www.ag-grid.com/react-data-grid/infinite-scrolling/)。

使用流程：

1. 聊天得到结果后，点击“编辑条件”进入自助核验，保留实际执行的条件。
2. 选择人员明细字段或最多两个分组、五个指标；支持多个部门与学校/专业多值 OR，其他条件之间 AND。
3. 列头筛选和排序发送到后端，先授权再筛选、统计，最后分页。每页50条，显示完整匹配数。
4. 比例同时显示分子、分母；平均值显示有效样本数。合计在完整人群上重新计算，不累加百分比。
5. 双击指标或点击图表下钻到相关人员。比例下钻显示分子；净增需分别查看入职、离职。仅返回解释该结果需要的字段。
6. “独立对账”比较只读 SQL 与另一份 Python 逐人员计算；对账覆盖全量结果，不只当前页。返回逐行差异数和哈希。
7. 有导出权限的角色可导出全部匹配记录为 CSV，敏感权限重新检查，单元格进行公式注入防护。

未知分组和部分关系组合暂不提供一键下钻，明确提示而不扩大条件。图表超过50个分组时要求缩小条件，不展示不完整的当前页图表。

## 验证方法与当前进度

确定性查询以 `evaluation/demo-v2-plans.json` 中人工定义的计划对照独立参考计算。运行时模块不读取这些预期计划。`reference.py` 的权限使用独立 BFS，统计不复用 SQL 编译器；比例和平均值统一四舍五入至2位小数。

真实模型评测脚本 `scripts/evaluate_v2.py` 串行访问本机 LM Studio，在临时目录生成数据、保存历史并恢复多轮问题；保留每题模型原始计划、修复轨迹和数值对比。首轮/试跑报告保留失败，最终放行以完整20题报告和回归结果为准。

当前页面已经完成表格筛选、统计和下钻的浏览器实测；完整模型评测与最终回归仍在进行。具体最终结果以后续验收报告为准。
