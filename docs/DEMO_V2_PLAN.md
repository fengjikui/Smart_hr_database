## 演示的数据与口径

1. 使用独立、可重建的合成数据，固定种子和快照。关系案例保留用户提供的已知关系；其他教育、年龄、合同等属性均明确为模拟值。
2. `person_id` 与工号分开；未提供的真实人员 ID 使用明确的模拟 ID，不将工号当真实主键。未确认的领导使用可识别的占位记录，不自动合并“杨xx”和“杨永民”。
3. 以一人一行的当前宽表组织演示源。优先实现20题依赖的25个字段，其他字段可浏览定义，不假装全部可执行。
4. 历史入离职按当前部门归属；不还原历史任职与汇报线。离职样例保留，以便演示期间事件统计；该保留规则是演示假设。
5. 未来合同到期日期是有效的业务日期筛选，不应被“历史事实不得晚于数据快照”的规则统一拦截。
6. 毕业时间、当前教育记录、年龄基准、招聘及用工类型均在配置中说明演示含义，后续可按业务口径修订。
7. 真实源目标为 PostgreSQL。演示数据与连接适配独立于现有 SQLite 合成库；接入实际 PostgreSQL 前不能声称方言或真实源已验收。没有真实连接参数不阻碍生成本地模拟数据和权限用例。

| M3：回答与连续使用 | 针对问题的中文结论；显示分子分母；多轮继承/替换条件；历史列表、恢复、继续提问 | HR-19/20及多轮测试通过；刷新不丢历史；身份变化后不泄露旧结果 |

每个阶段单独提交、测试并展示可操作结果。实现使用独立分支与测试状态，验证时不覆盖已有看板或会话；只有阶段检查通过后才替换现场演示版本。

### M1：权限配置如何展示

将人员关系规则与角色能力分开维护：

- 人员范围：本人、全部管理线下属、本人HRBP服务对象、继承下属HRBP服务对象。
- 角色能力：基本人员、教育、任职、合同等字段组，明细查询、导出、规则管理等功能。
- 业务待确认项：部门主管是否额外授权，默认不从 `dept_master_id` 自动推导一个新权限来源。

第一版角色示例为 HRBP、HR主管、部门主管、普通员工；规则配置由独立的演示配置管理员操作。管理员能改演示策略，不因此隐式成为所有真实业务数据的读取者。

配置页应支持“修改 → 预览新增/移除范围 → 应用 → 查看版本”。预览与应用均鉴权。应用后重新计算权限；查询、看板、导出、追问及历史读取统一校验当前策略，不能只有聊天接口受控。

每个人员返回可解释的授权路径。王承哲经姜姜的 HRBP 服务关系查看王灏与冯基魁，是首要正向用例。并准备同名人员、工号前导零、多条授权路径、自服务 HRBP、无上级、管理环、删除 HRBP 服务、换主管等对照用例。管理链无固定业务层数上限，但必须去重、检测异常并保证结束。

### M2：查询能力如何扩展

延续 LangGraph 和元数据逐步读取，增加结构化查询描述，覆盖：

- 明细列：从允许字段中选择输出列；排序、分页和总数分开处理。
- 筛选：多个部门/人员的 OR 集合，与日期、学历、专业、用工等条件组合。
- 聚合：计数、平均值、条件计数、比例和日期差等受控表达式，可返回多个指标及最多两个分组维度。
- 日期：相对期间转确定边界，入职、离职、合同到期等不同日期字段分别建模。
- 既有指标：继续引用审核口径；自助组合使用同一受控表达式体系，不要求每个字段组合预先取一个指标名。

模型选择字段、条件和计算；权限及允许的表、列、表达式由服务端验证，SQL值使用绑定参数。所需信息不充分时询问用户或说明缺口，不删掉难处理条件再执行。

语义检索增加能力、字段、枚举和日期含义的关联。20题只用于验收，不从题目ID直接返回预设业务数字；冻结验收集后增加独立口语改写。

### M2：自查询核验页面

表单提供人员范围、部门多选、期间、输出列、条件、分组与指标。用户可以直接操作，也可以从某条聊天结果带入条件后修改。

同屏展示：

1. 用户选择的条件，以及与聊天计划的差异。
2. 表格/图表、分子分母、总数、分页提示和统计口径。
3. 独立参考结果、逐组或逐人员差异和所用数据版本。
4. 对应调试记录，定位到第一处不满足预期的节点。

表单与聊天共用授权和执行边界，用于核验意图；“两者使用同一计算引擎得到相同数字”不是独立数值正确性证据。演示参考计算需要独立实现，不调用被测SQL编译器；权限另从源关系独立遍历对照。参考结果同样限制在当前授权内，不能通过核验界面绕过权限。

### M3：自然语言、多轮与历史

- 结论明确说出问题中的对象、日期和数值。例如“2026年4月至6月，授权范围内入职且目前已取得博士学位的员工共X人”，X来自实际计算。
- 表格和图表与结论共享同一结果，不生成数据中没有的原因或趋势推断。聚合可使用确定性表达模板；需要模型组织文字时限定输入为获准结果并核对引用数字。
- 追问保存结构化条件：哪些继承、哪些替换、哪些新增。支持改时间、改部门、追加学历筛选、聚合转明细。
- “这些人”若指上一轮完整筛选人群，继承筛选；若指排序后的前N人或选中的人员，记录明确的选择语义，不能默默扩大成全部人。
- 历史按当前身份隔离，支持列表、查看、恢复和继续提问。展示原数据/口径版本；恢复时按当前权限检查并标明重算结果，不混淆原历史数字。
- 权限减少、身份切换或角色变化后，历史、调试、导出和看板遵守同一撤权规则。浏览器异步旧响应不能覆盖新身份数据。

## 回归与发布标准

首批新增规模：20个标准业务问题、每题2个改写共40条、至少20条权限及边界、至少10条多轮/历史。保留既有有效测试；变化的业务假设应显式更新预期及说明，不能为了通过而删掉安全断言。

逐节点断言覆盖身份集合、语义ID、关键字段、筛选与时间、补读/澄清分支、最终计划、执行参数、结果及摘要。允许等价SQL和不同合法补读路径，不硬编码模型全文或SQL字符串。

先核对源数据，再验证确定性执行，随后串行调用真实 LM Studio 验证完整链路。模型评测与数据对账分开报告；既有代码补偿后的成功不能宣称模型原始识别正确。

M4放行要求：20题完整链路全部通过、关键权限负例全部拦截、逐人员/逐组差异为零、数字引用无错误。比例和平均值使用事先定义的舍入规则。若存在未解决失败，保留失败记录并说明，不能将案例从20题中临时移除后宣称通过。

前端检查桌面与窄屏、键盘操作、加载/空/错误状态、角色切换、历史恢复、表格分页与图表一致性。主题与聊天布局作为该阶段的易用性改进，核心流程保持清晰，不让装饰性重做阻塞验收。

构建和批量推理前及运行中检查本机负载、可用内存与可取得的热状态；模型串行执行、按组运行，压力升高时降载或暂停。数据和应用状态使用临时目录，避免污染现场演示。

## 后续业务沟通时需要展示的配置

字段映射与口径版本、关系来源、HRBP继承开关、角色字段组、明细/导出能力、时间与空值规则、标准问题及预期结果。调整其中一项后，预览影响并运行相关回归，再发布新版本。

员工关怀、任意跨库分析、完整矩阵角色系统、通用多企业框架、真实OA联调属于后续扩展。当前首要成果是上述范围内可解释、可复核、可恢复的演示版本。
