# 教育背景与组织分析设计

版本：`hr-data-2` / `hr-metrics-1.1`。所有员工和教育经历为合成数据，默认种子20260911，480名员工、459名在职，数据截至2026-09-11。日期按数据截止日解释，不能把固定演示日期当作电脑今天。

## 档案、经历与字典

| 表 | 粒度 | 新增字段与职责 |
|---|---|---|
| employees | 每名员工一行 | `highest_education`最高已完成学历、`highest_degree`对应学位、`graduation_school_id`院校、`major`专业、`graduation_date`毕业日期、`education_mode`学习形式；六个字段为当前快照 |
| employee_education | 每人每段已完成教育经历一行 | `id,employee_id,school_id,education_level,education_rank,degree,major,start_date,graduation_date,study_mode`；保存本科/硕士/博士等不同学校与阶段，历史查询以此表为准 |
| schools | 每所院校一行 | `id,name,aliases,is_985,is_211,classification_basis,source_url`；别名归一、项目标签、来源。业务定义由HR维护，不能由模型猜标签 |
| overtime_attendance | 每人每周末打卡日一行 | `id,employee_id,day,check_in,check_out,break_minutes,work_minutes`；独立核验周末申请工时 |
| overtime_requests | 每人每日一条申请 | 新增`day_type`工作日/周末；保留申请分钟、审批状态、审批人 |

当前共有24张业务表、8个应用逻辑表/全文索引、188个字段、17个指标。完整逐字段说明、主外键、CHECK、索引和实际DDL见 [完整数据字典](DATA_DICTIONARY.md)，机器版见 [data-dictionary.json](data-dictionary.json)。网页“数据库与口径”由相同的结构读取器生成；“指标字典”末尾可展开院校及简称。

教育学历与学位分开存。高中及以下、专科、本科、硕士研究生、博士研究生分别为层级1–5。模拟经历的学位为无学位、学士、硕士、博士，不能用“博士后”替代博士学位。学习形式、专业目前只展示，尚未开放自然语言筛选。

## 先确定口径，再执行查询

| 问法 | 默认口径 |
|---|---|
| 某部门博士人数 | 统计日仍在职、最高已完成教育经历取得博士学位的去重人数，包含该部门下属团队 |
| 上季度入职博士人数 | 上一完整自然季度入职，学历取入职当日已完成的最高经历；即使后来离职仍算该期间入职 |
| 某校毕业员工数 | 任一已完成教育经历毕业于该校；学校字典精确匹配名称或别名 |
| 几所学校毕业员工数 | 学校条件OR合并、按员工去重。一个人清华本科、北大硕士只计1人 |
| 最高学历毕业于某校 | 只匹配最高已完成教育经历对应院校 |
| 某校硕士毕业人数 | 同一条已完成经历同时满足该学校与硕士学位，不能用清华本科和北大硕士拼成清华硕士 |
| 硕士占比 | 最高已完成教育经历取得硕士学位人数/同组织全部授权在职人数；默认精确硕士，不包含博士 |
| 硕士及以上学历占比 | 最高已完成学历层级≥硕士研究生，包含博士 |
| 211或985占比 | 默认最高已完成教育经历院校标签匹配；211包含985，合并按OR，不相加 |
| 上季度入职员工中博士占比 | 分母改为上季度入职的全部授权员工，分子取其中入职日已经取得博士者；不使用当前在职人数作分母 |
| 今年各部门入职/离职 | 1月1日至数据日；分别按入职日和离职日计数，任职归属取入职当日和离职前一天。内部调动不算离职 |
| 各部门周末加班总工时 | 默认本月，周六/周日已批准申请分钟数之和÷60；独立打卡核验申请不超过净工时。待审批、拒绝不计入 |

占比分母不会应用教育筛选，教育未知者也包含在分母内；分母0返回空值而不是0%。SQL保留两位小数，返回分子、分母和百分比。人员明细既展示最高学历，也在有教育筛选时展示“本次匹配的毕业经历”，解释为何某校本科、其他学校硕士的员工仍匹配某校查询。

“各部门”汇总到三级部门，包含四级团队；公司或事业部直属人员单列，避免遗漏负责人。“各团队”按具体任职组织分组。入离职组合以及周末加班会为无事件的授权组织补0，图表前12组之外可看完整数据表。计划保存到看板后，每次打开重新鉴权、重新计算，教育条件和期间会保留。

## 院校标签依据与限制

当前院校字典有11条：清华、北大、复旦、上海交通、浙江、同济、华东理工、上海大学，以及明确标注“模拟”的澄川大学、澄川职业学院和澄川中学。这里只收录演示子集，不能假定覆盖全国院校。

真实项目标签参考教育部的[985工程学校名单](https://www.moe.gov.cn/srcsite/A22/s7065/200612/t20061206_128833.html)和[211工程学校名单](https://www.moe.gov.cn/srcsite/A22/s7065/200512/t20051223_82762.html)。985院校同时满足211标签，数据库约束为`is_985 <= is_211`。分类是历史工程名单，不代表“双一流”、全球排名或个人能力评价。正式接入需维护院校更名、合并、独立学院/校区、国外学校、毕业证验证及标签版本。

当前多校仅支持OR合并，最多5所；“逐校分别”“同时毕业于这两校”需拆开提问。未收录院校、双一流、博士后、自由多维度/多指标组合会明确提示，不忽略条件。工作日加班单独汇总尚未开放，可使用批准加班总工时和周末子集；真实调休制度接入后还需区分自然周末与法定休息日。

## Agent执行与存储

流程为：接收问题 → 计算授权集合 → 检查支持条件/归一院校与组织 → 注入已授权指标元数据 → 本地LM Studio生成结构化计划 → JSON结构校验/最多重试一次 → 核对用户明确条件 → 再次鉴权 → 参数化SQL编译 → 只读数据库执行 → 结果口径与图表 → 审计、保存本轮计划。

模型不生成可执行SQL。明确的学校、学位、组织、季度、年度、周末及入离职组合条件不能被静默省略；校正保留在“意图与计划校正”节点，展示原始模型值和执行值。空模型计划不回落成默认人数查询；触发结构修复重试。此机制针对明确条件，不是所有自然语言歧义都已解决的保证。

查询使用教育经历`EXISTS`而非直接一对多聚合连接，防止重复计算人数和考勤工时。比例分子采用条件去重计数，分母独立于教育条件；所有事实必须先连接当前授权员工集合。教育完成时间与任职归属使用事件日，不拿当前快照改写历史。

存储分工：HR关系数据在`data/hr.sqlite`；指标定义在Git版本化`semantic/catalog.json`，发布到`data/app.sqlite.metrics`；FTS5是指标搜索派生索引，不保管人员教育经历。学院名称与别名在学校关系表，当前规模无需向量库。查询计划、看板、会话、调试在应用库；每个调试节点保存真实输入/输出并按身份和授权指纹隔离，不保存模型内部推理。

## 模拟校验与升级

教育经历与周末出勤使用独立随机数序列。层级受入职年龄约束，毕业先于入职，教育阶段不重叠，最高快照与经历一致；上季度包含博士入职样本。周末出勤有独立打卡、休息分钟和三种审批状态，不挤入应出勤率分母。

32项数据不变量覆盖教育快照、层级/学位对应、日期顺序、项目标签、周末日期、净时长、申请时长与原有任职考勤规则。查询测试以原表独立Python汇总对数，覆盖学校重叠、分母、未来毕业日期、未知教育、历史调岗、无事件部门、权限、导出和看板重放。

启动时发现旧版合成库，会先备份业务库和应用库到`data/backups/`，再按原种子、人数、截止日重建业务数据；校验通过后原子替换。真实库不允许自动重建。保留应用库；旧目录v1.0看板的department分组迁为team，维持旧版“具体任职组织”的语义。请勿把`--reset-app`用于常规升级。
