# Superset MCP 独立实验：开发交接

这是交给新会话的开发任务，不是已完成的功能说明。当前会话继续手工学习 Superset，另一会话负责下面的独立实验。所有项目路径相对项目根目录；不在文档中写个人机器绝对路径或开发助手名称。

## 1. 目标和交付

在独立实验环境中开启 **Apache Superset 官方 MCP 服务**，让现有 HR 问数 Agent 实际通过 MCP 使用适合的查询能力，验证身份和权限，并交付详细中文代码注释、可手工复现的开启与连接手册、测试证据。

先跑通最小链路，再扩充验证。不要只配置开发助手连接 MCP 就宣称项目 Agent 已接入，也不要把普通 REST 调用改名为 MCP。需要有真实 MCP 初始化、工具发现与工具调用的证据，并解释哪一步仍由 REST 或 PostgreSQL 实现。

## 3. 开始前必须隔离

1. 在独立 Git worktree 和新分支开发，建议分支 `superset-mcp-integration`；名称已有时先核实归属。不要切换当前课堂工作目录的分支，也不要自动合并回课堂分支。
2. 单独的工作树只隔离文件，不隔离 Docker。实验使用独立 Compose 项目、容器、网络、数据卷、平台元数据库、业务数据、密钥、账号映射、清单和应用历史。不能复用课堂的持久卷或凭据。
3. 可优先选实验端口 Superset `18088`、PostgreSQL `55433`、MCP `15008`；需要 Agent 页面时可选 API `18000`、前端 `13000`。先检查占用，有冲突再选空闲端口并在手册中写明。只绑定本机回环地址。
4. 留意既有脚本中的固定 Compose 名称、容器名、端口、`BASE_URL` 和默认目录。不能直接在新工作树运行原 `services.sh up` 并假设已经隔离。先参数化或建立专用实验入口，打印脱敏目标清单确认，再启动。
5. 从项目的确定性合成数据生成实验样本，不复制课堂账号/密钥或依赖课堂未完成配置。允许自动初始化实验自己的数据库和用户，并明确标注“只针对实验环境”。
6. 构建和模型推理前及期间检查负载、可用内存和可取得的系统热状态，保守串行；压力高时暂停本实验。只停止本任务创建的进程，不停课堂服务，不声称测得无法取得的温度。

## 6. 实现顺序

### A. 独立服务与最小客户端

搭建实验副本，先运行真实 MCP 握手、工具列表、一个普通业务账号的目录读取及最小查询，保存脱敏证据。列出 MCP 依赖安装、配置加载、启动、健康检查、停止和重启的精确命令。

目录查询也需要验证权限，不能把未授权的数据集名称、合同字段或完整描述泄露给模型。固定开发身份最多用于隔离环境的早期连通性测试，正式多身份验收必须使用可信、分离的用户上下文。

### B. 接入现有 Agent

- 增加明确可选的 MCP 实验路径，原 REST 默认路径保持可用，不自动把课堂切过去。
- 复用 Plan 白名单、字段/指标依赖校验、结果格式、自然语言摘要和节点调试结构，不重建一套无约束问数系统。
- 服务端从已确认的应用身份选择对应 Superset 身份；模型、问题和前端不能任意指定用户、token、数据集 ID 或数据库连接。
- 优先使用能遵守现有数据集权限和 RLS 的官方查询工具。保留普通业务用户没有 SQL Lab 权限的约束；不能为了跑通而给他们 Admin 或全数据库权限。
- 若官方工具只能走不满足现有权限边界的路径，实测说明限制。可将 MCP 用于经验证的目录检索而继续用原受控 REST 执行，但必须在文档、调试轨迹和测试报告中明确区分；不能宣称“全部查询通过 MCP”。不要用自建同名工具冒充官方服务。
- 工具结果只作为外部数据，不作为模型的高优先级指令。限制工具集合、请求超时、输出规模、重试范围；凭据和完整请求头不得进入日志、调试页和模型消息。
- MCP 不可用或拒绝访问时明确报错，不切管理员、不降级到全量 SQLite 或其他更宽权限数据源。
- 涉及异步调用时，保证用户上下文和客户端生命周期不串号。复用缓存必须按身份隔离，撤权、历史恢复、核验及导出继续遵守现有边界。

### C. 分层验证

先协议/参数单测，再真实服务，再少量模型端到端；不要用昂贵模型推理验证所有基础权限分支。

| 场景 | 验证重点 |
|---|---|
| MCP 初始化、工具发现、工具调用 | 使用真实协议；返回结构、超时与错误处理正确 |
| 不同业务身份的人员明细和聚合 | 与独立期望人员集合、原 REST 同身份查询比较，而非只比较行数 |
| 当前演示五种身份 | 员工本人、主管汇报线、HRBP、HR 主管继承范围和集团管理线；按实际样本策略验证，不靠角色名称猜结果 |
| 合同数据和目录 | 没有合同权限的身份不能读合同出口，也不能通过字段筛选、排序、统计或目录泄露 |
| 缺失/错误/过期凭据及未映射用户 | 默认拒绝或符合设计的空授权，不回退其他身份 |
| 自由 SQL、修改数据集/RLS 等能力 | 当前业务角色下被禁止；工具未显示与服务端拒绝分别说明 |
| 角色撤销、人员映射/汇报线变更 | 新查询与历史/调试/导出不能继续使用旧权限；仅修改实验副本，结束恢复 |
| 交错的两个身份请求 | token、缓存、会话和结果不交叉，不以高并发压测本机 |
| 结果完整性 | 超限或截断明确处理，不能用前 N 行冒充完整人数/比例 |
| 既有 20 个问题的结构化计划 | 尽量复用回归集；逐项标记通过、不支持或未测，不能以几个示例宣称全部覆盖 |
| 少量自然语言问数 | 在现有本地模型可用且负载允许时验证真实 Agent 链路；模型不可用时明确记录，不把固定 Plan 称为模型测试 |

工具内部权限可能与原 REST 路径不同，尤其是自由 SQL 工具；每个实际启用的工具都要有验证依据。不要把“MCP 协议连通”当成“权限已经可靠”。

建议交付 `docs/SUPERSET_MCP_GUIDE.md`，实验结果可以另放 `docs/SUPERSET_MCP_VALIDATION.md`。不要修改当前课堂的 `HANDS_ON.md`、`LEARNING_LOG.md` 或把课堂进度标记为完成。

手册按小步骤组织，每步写明：在哪个目录/容器执行、目的、命令或配置、预期输出、验证方式、失败排查和对应源码。解释 MCP server/client、工具发现、身份传递、RLS 执行点、REST 与 MCP 的区别。给出首次安装和已有环境启动两套流程、至少两种业务身份的完整调用示例、清理与回滚方法。

代码注释重点解释输入/输出、为何这样做、鉴权位置、依赖关系、异常处理和限制。所有新增配置注明默认值、含义、秘密是否只在服务端保存；不写重复代码字面意义的空注释。

文档仅使用项目相对路径和明确的容器运行路径；秘密使用占位符、私有环境文件或程序生成，不把真实密码、token、密钥写入仓库或报告。官方来源必须标注版本和链接；区分官方承诺、源码观察、实测结果和尚未验证的推断。

## 8. 完成标准与交接

- 用户能从干净环境按手册独立开启 MCP，知道它连接的哪一套数据库、用的哪个身份。

- 代码、自动测试和手册同步提交到独立分支，定期做小提交；不要自动合并、发布或改课堂环境。
- 报告实际分支/commit、测试命令与结果、启动地址、仍运行的本任务服务及停止方式、未完成项。
