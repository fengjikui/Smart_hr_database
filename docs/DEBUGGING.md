# 节点调试与问题定位

## V2 独立调试页面

打开 `/demo/debug`，或在 `/demo` 左侧选择“节点调试”。每条聊天结果的“查看节点调试”会在新标签页打开 `/demo/debug?run=<记录ID>`，保留原聊天便于对照。成功、需要澄清和权限限制的已保存记录均可查看；旧回答无需展开表格即可进入调试。

左侧列出当前身份最近100次可访问的已保存查询；选中记录后按实际执行顺序列出节点名称和耗时，点击节点查看输入、输出。较宽窗口并排显示输入输出，窄窗口纵向排列。页面显示节点累计耗时（不等于含网络、排队等开销的总耗时），并支持查看完整返回结果和跳转上一轮查询。刷新保留URL指定的查询；“刷新查询记录”用于读取后来完成的问数请求。

数据复用 `/api/v2/history` 与 `/api/v2/history/{id}`，服务端同时校验记录所有者和当前授权/数据指纹。身份切换会清空旧视图；其他身份或权限变更前的旧链接返回404。页面读取记录不触发模型调用。V2只保存完成后的执行链路，没有运行中逐节点推送；在保存前发生的HTTP错误不会补造记录。没有trace的历史记录明确显示“没有保存节点信息”。聊天中的表格筛选仍保留当前SQL详情，节点链接始终指向原始问数请求，不冒充后续手工筛选过程。

以下内容描述保留在 `/` 的原版工作台，其运行中轮询和接口与V2不同。

本次新增“数据库与口径”和“节点调试”页面。浏览器打开 http://127.0.0.1:3000/，左侧选择页面。完整技术数据字典仅公司负责人演示身份可读；各身份均可调试自己的问数请求。

## 使用方式

1. 在“智能问数”提问，点击该条回答下的“查看本次节点输入与输出”；成功、澄清、拒绝及进入执行链路后的报错都支持跳转。
2. 也可直接在“节点调试”输入问题，点击“运行并查看节点”。这是同一 `/api/chat` 执行链路，调用当前配置的真实 LM Studio 模型。
3. 左侧按实际执行顺序列节点，右侧同时列该节点输入、输出、耗时和错误。每2.5秒读取最新状态，模型尚未返回时也能看到发出的请求。
4. 使用记录选择器切换当前身份最近50次运行。展开“最终响应与运行错误”查看返回给问数界面的完整结构。
5. 选中一次成功运行后，可勾选“继承当前成功查询作为追问上下文”。页面显示实际使用的 conversation_id，取消勾选后独立提问。

新查询才记录调试过程，更新前的历史查询无法补造节点。本轮没有将总览、固定看板或直接 `/api/query` 调用伪装成 Agent 运行。鉴权、CSRF、请求体校验和限流等在进入 Agent 前失败的请求，不产生运行记录；这些由 HTTP 状态和现有安全日志定位。

## 真实节点及输入输出

| 节点 | 输入 | 输出与排查用途 |
|---|---|---|
| 接收问题 | 原问题、前次对话ID | 本次问题和接收时间 |
| 身份与人员范围 | 当前会话主体ID | 授权属性、人员ID集合、候选数、策略版本；候选数含历史离职员工，不等于在职人数 |
| 能力边界检查 | 原问题 | 是否命中未开放条件、规则和命中文字；拦截后不会执行模型或SQL |
| 截止日与前次计划 | 当前身份、前次对话ID | 数据日、同身份前次计划 |
| 语义检索与披露 | 问题、显式条件、发布指纹 | 权限过滤后的别名/全文命中、实际披露文档、遗漏字段、字符预算 |
| 补充读取 | 模型inspect或执行必需ID、已用轮数 | 重新鉴权后的定义、检索结果、剩余轮数；最多两轮 |
| 模型并发检查 | 并发上限1 | 是否有执行空位；忙碌直接返回429 |
| 本地模型调用 | endpoint、timeout、完整消息、JSON Schema和推理参数 | HTTP状态、usage、finish_reason、解析后的模型候选输出；不显示内部思维链 |
| 查询计划结构校验 | 模型候选、QueryPlan Schema | 类型化计划或字段校验问题 |
| 结构错误修复重试 | 重试次数 | 实际追加的修正消息；最多重试一次，随后会出现第二次模型和校验节点 |
| 明细意图与计划校正 | 问题、模型原计划 | 是否修正、规则、最终执行计划；可分辨模型输出与代码修正 |
| 返回澄清或拒绝 | 计划 | 给用户的提示，明确未执行数据库 |
| 执行前重新鉴权 | 初始授权 | 最新启用状态和授权集合 |
| 权限校验与 SQL 编译 | 最新授权属性、类型化计划 | SQL、命名绑定参数、过滤后人员ID、日期和维度；范围在聚合前加入SQL |
| 执行只读 SQL | SQL、参数、允许表、超时限制 | 真实行数和行数据；薪酬原始聚合结果不记录 |
| 聚合保护与空值处理 | 指标、行数、最小组规模 | 经过小组与互补隐藏处理的可展示行 |
| 格式化结果与统计口径 | 指标定义、执行计划、保护后结果 | 最终表格、图形建议、口径、权限说明、SQL和摘要 |
| 写入查询审计 | 当前主体、指标、耗时、范围 | 实际审计写入结果 |
| 保存本轮查询计划 | 主体、计划和结果状态 | conversation_id，供后续追问使用 |

各条执行路径的节点数不同；未出现表示没有执行，不补“成功”占位。出现失败节点后若修复成功，整次运行可成功，但保留第一次失败原因。节点耗时包含记录写入开销；正在执行的节点显示“执行中”，完成后才有最终耗时。

## 推荐排查顺序

- 问题直接被拒绝：先看“能力边界检查”命中项，再看模型是否选择了 refuse/clarify。
- 回答了别的问题：对比“本地模型调用”的候选计划与“明细意图与计划校正”的最终计划，检查 metric、dimension、period、relation 和过滤字段。
- 人数或组织不对：比较当前授权集合、编译后的人员范围、绑定日期；分清“当前授权候选人员”和“统计日在职人员”。
- 数值不对：用“数据库与口径 → 指标与公式”的实际表达式核对数据库节点的结果，检查分母、空值、日期边界和历史任职归属。
- 模型慢或离线：查看模型节点的请求参数、HTTP状态、超时与usage。固定看板不调用模型。

## 存储、权限和留存

`data/app.sqlite.debug_runs` 每次运行一行，payload 存节点JSON，按 owner_id 和开始时间索引。节点开始、结束、运行结束均持久化，进程重启时将尚在运行的记录标记为中断。默认每身份保留最新50次记录，尚在执行的记录暂不清理，因此并发边界时物理行数可能暂时多于50。它是本机调试存储，不是生产集中可观测平台。

读取必须同时匹配当前身份和授权指纹。指纹包含角色、授权根、功能权限、当前人员集合与策略版本。公司负责人不能查看其他身份的调试记录；授权变化后旧记录不可读，避免从历史结果继续获得已撤销的数据。前端切换身份会重新装载，不沿用另一身份的数据。

完整数据库结构接口当前仅向公司负责人演示身份开放；实际产品应改为单独的元数据管理权限。接口只读取技术结构与业务表合成行数，不采样私人字段或会话值。

凭据字段键（Cookie、Authorization、CSRF、令牌摘要、API key、password等）及常见Bearer/sk密钥模式会脱敏。模型显式内部推理内容不记录；本地适配器若把独立JSON计划放在 reasoning_content，只保留可解析的计划。薪酬原始查询行不持久化，只有保护后的值进入可查看结果。其余已授权业务结果可能包含员工名等资料，**不能将此机制视为通用个人信息匿名化**。

每段数组最多500项、对象最多1000字段、文本最多40000字符；截断有明确标记。日志不提交Git、不上传外部服务。真实企业数据接入前，应明确调试角色、按需采集、字段级脱敏、加密、到期删除和集中日志访问审计。

## 接口与测试

- `GET /api/debug/runs`：当前身份且当前授权仍有效的最近运行摘要。
- `GET /api/debug/runs/{id}`：一条运行的实际节点、输入输出和最终状态。
- `GET /api/data-dictionary`：实际表结构、字段、外键、索引、DDL、指标定义、实际SQL表达式、存储和共用口径。
- `POST /api/chat`：成功/澄清/拒绝响应带 debug_run_id；进入Agent后的HTTP错误通过 X-Debug-Run-Id 响应头关联运行，同源代理保留该头。

`tests/test_debug.py` 覆盖真实适配器请求内容（HTTP MockTransport）、执行中可见、结构错误重试、超时、拦截、推理信息排除、薪酬保护、跨身份读取、撤权、身份认证、字典与实际结构一致、运行中断恢复及留存。真实 LM Studio 和浏览器验证另见 `docs/TESTING.md`。

本轮查询由实际LangGraph编排，“语义知识库→查询流程”直接读取编译图。最终调试摘要显示模型调用次数、补充读取次数、披露条目数与语义指纹。结构修复最多一次；完整流程及元数据权限见[语义层与LangGraph](SEMANTIC_ARCHITECTURE.md)。旧版本调试记录不会补造新节点。
