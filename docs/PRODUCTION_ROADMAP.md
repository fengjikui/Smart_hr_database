# 从演示到企业上线

## 优先约哪些人，带回什么

| 对口人 | 必须拿到的材料或决定 | 用于完成 |
|---|---|---|
| 业务主管、HR负责人 | 前20个高频问题、使用者、正确答案样例、优先级、验收人 | 范围与验收集 |
| HRIS/数据仓库负责人 | 宽表DDL、逐字段解释、脱敏样本、数据粒度、主键、日期与更新机制、历史保留 | 真实数据映射与质量规则 |
| 组织人事负责人 | 员工/组织稳定ID、直属与虚线关系、代理负责人、组织变更历史 | 人员范围与时态授权 |
| HRBP及薪酬负责人 | 服务组织映射、薪资字段能力、聚合/明细/导出差异、例外审批 | 权限矩阵与授权责任 |
| 考勤负责人 | 弹性规则、午休、实际应出勤、假期调休、补卡、半天假、跨夜班、加班认定 | 正式考勤与加班口径 |
| IAM/IT负责人 | OIDC/SAML/企业登录接入、账号停用事件、身份到员工映射 | 真实认证与撤权 |
| 信息安全与隐私负责人 | 分类分级、允许的模型部署、日志留存、导出审批、密钥与主机基线 | 安全设计及上线验收 |
| DBA、平台运维 | 只读访问方式、预期数据量、峰值并发、延迟目标、备份恢复与监控目标 | 容量、可靠性与部署 |

演示阶段拿不到的资料已采用明确假设，不能让这些假设在真实上线时默默成为制度。例如“部门负责人能看全部历史下属”与“只看现在管理的人”是不同授权策略，必须由数据责任人决定。

## 分阶段工作包

1. **业务与数据契约。** 确认10–20个问题及标准答案；宽表映射主题视图；识别无历史、缺日历、重复人员等问题。交付字段映射、口径签字版本、质量检查与不可用指标清单。
2. **身份与授权底座。** 替换演示切换入口，接SSO；后端映射可信主体；授权包含人员集合、字段/指标能力、操作、有效期及数据日期策略。同步停用与组织变更，建立授权审批和审计。
3. **数据库与语义层。** 业务只读副本/视图，PostgreSQL RLS或目标平台等效行安全、受限列视图、独立服务账号、连接池隔离；指标定义Git评审后发布到运行目录，变更触发黄金问题回归。
4. **查询质量。** 收集真实问法与歧义，扩展类型化计划，做到每个过滤条件有可验证表达；不支持条件必须澄清。对答案正确性、权限拒绝、多轮继承分别打分，不能只验SQL能跑。
5. **企业看板与性能。** 定义私人/团队分享、访问时授权、订阅与导出审批；缓存按主体、授权版本、口径和数据版本隔离。根据实测加入分区、汇总表、队列与预算，复杂查询异步执行。
6. **生产运维。** HTTPS、密钥管理、集中追加审计、指标与告警、备份恢复演练、迁移/回滚、灰度；CI门禁与指定内网环境的CD对接。落实服务负责人和事故处理流程。

## 必须解决的难点

- **语义正确**：能执行的SQL不一定回答了问题。离职率分母、历史组织归属、未完成考勤、部分月份必须显式定义。
- **权限贯穿全链路**：对话、组织搜索、结果、看板、缓存、导出及后台订阅都要重验；一次登录时过滤远远不够。
- **历史与当前关系**：调岗、离职、兼岗、矩阵管理使当前组织树不足以表达历史范围。需要时间有效的事实与明确的授权策略。
- **敏感聚合推断**：少量人员的均值、任意过滤与反复差分会泄露个人情况。最小群体阈值只是基础，生产需限制查询形状和组合，并审计异常行为。
- **真实企业数据质量**：宽表粒度不清、一个人多条、空值含义不明和旧代码映射会直接扭曲指标，应先验数据，再验模型。
- **模型与确定性边界**：模型负责理解与澄清，授权、执行、计算与审计必须由程序和数据库负责。知识检索结果也不能成为权限授权来源。

## 好用的验收重点

用业务方认可的黄金问题集衡量：答案与基准一致、重要条件不丢失、口径可理解、范围可见、越权有明确处理、模型故障不影响固定看板、常用问题保存方便。将支持范围、复杂查询等待时间和反馈通道直接放入产品，不让用户靠试错猜能力。

实际交付节奏取决于真实数据、身份接口及责任人可用性。本演示已完成本地开发、测试、生产模式启动与发布脚本；企业SSO、真实数据、独立渗透测试、生产负载和远程CD不应被标记为已完成。
