# HR 演示 V2：建议现场演示顺序

入口：`http://127.0.0.1:3000/demo`。启动命令：`npm run demo:production`。修改前端后先构建再重启。右上角是演示身份，不是真实登录。

所有数据均为合成记录，数据截止日固定为2026-09-11；历史统计按当前部门归属，不还原当时的组织关系。

## 1. 先展示一张可操作的表（2分钟）

选择“HR主管 · 王承哲”，进入“自助核验”。保留工号、姓名、部门，再勾选学校，点击“应用条件”。默认可见226名在职员工，分页显示50条。

在学校列输入“清华”，完整匹配人数变为41。点击“独立对账”，应显示核对41行、差异0。说明统计并非针对当前页，也不是模型随口给出的数字。

点击“编辑条件”，切换“分组统计”，保留部门分组、人数，再选择“硕士及以上占比”。再次应用条件，平台研发部显示9人，其中硕士及以上3人，占比33.33%。双击占比，打开这3人的明细，只包含解释本题需要的字段。

学校列按当前宽表的教育记录判断；这里的学历比例分母是已经筛选为清华的人群。如要统计整个部门的学历比例，先清除学校条件。

## 2. 再展示自然语言链路（3分钟）

在“智能问数”提问：

> 清华大学或北京大学毕业的在职员工，按部门分别有多少？

观察回答中的当前权限、在职条件、学校 OR 条件及部门分组。展开节点调试，说明目录披露、模型计划、明确条件绑定、校验、权限注入、SQL和结果分别在哪里发生。

继续提问：

> 在刚才清华或北大毕业的这些人中，只看硕士及以上、全日制员工，再按部门统计。

刷新页面，从“历史对话”打开这条成功查询，再提问：

> 把学校改成浙江大学，其他条件不变，并列出姓名、部门、学校、学历和专业。

检查学校条件被替换，学历、全日制与在职条件保留。还可以点击“编辑条件”，手工改变一个筛选，再做独立对账。

## 3. 解释汇报线和HRBP继承（2分钟）

“关系与权限”页用姓名列筛选王灏或冯基魁。王承哲并不通过直接管理线看到王灏，而是管理姜姜，再继承姜姜服务员工的权限。

切换“部门主管 · 王灏”，查看直属与间接下属。切换“员工 · 冯基魁”，可见范围仅本人，上一角色结果被清除，合同字段与导出入口不可用。

## 4. 讨论配置而非空谈规则（2分钟）

切换“配置管理员 · 集团管理线”，进入权限页。关闭HR主管的“继承下属HRBP服务”，先点击“预览影响”：候选人员239→60，撤回179人。

若现场要演示应用，点击“应用此配置”，再切回HR主管核对。旧权限下保存的历史不会继续展示。演示完后按同样步骤恢复该开关，保持后续题单的默认范围。

配置页还可以调整教育、任职、合同字段组，以及明细、导出能力。改规则须先讨论业务含义，再跑相关回归。

## 5. 对业务方明确范围（1分钟）

- `person_id` 为主键；工号为保留前导零的字符串。直接主管、HRBP和部门主管关联人员主键。
- 当前可执行数据仅26字段；完整源字段对照另见 `REAL_SOURCE_FIELDS.md`。
- 当前关系无历史；985/211字典和毕业日期映射仍需业务确认。
- 自助核验验证的是当前演示口径下计算正确；是否真正回答了业务意图，还需看实际条件并由业务确认。
- PostgreSQL连接、生产SSO、真实数据和组织权限尚未接入。演示身份选择不能直接作为生产鉴权机制。
